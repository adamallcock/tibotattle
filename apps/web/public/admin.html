Upload storage safety

Crash-safe object reconciliation

Checking storage…

Every upload object receives a crash-safety registration before its database commit. Recent registrations remain for one hour; reconciliation preserves objects referenced by accepted data and removes only unreferenced orphans. This is storage housekeeping, not moderation or a count of rejected submissions.

How to read the states

Recent: normal uploads still inside the safety window.

Due and referenced: valid objects whose temporary marker should clear.

Due and unreferenced: orphan candidates scheduled for safe deletion.

Collection stages

Bounded maintenance

Run the maintenance pass

Runs one bounded retention and object-reconciliation pass, then processes eligible aggregate rebuilds when publication is enabled. Work may remain after the request succeeds; review the result and queues. This does not initiate participant erasure.

Upload ingress

Ingress pressure

Shared upload budget state: in-flight leases against the concurrency cap, remaining start tokens, and content-free denial counters. Denials are cumulative for the budget state, not a last-24-hour error rate.
