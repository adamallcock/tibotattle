# GCP E-PT8 PT-8-lite cutover orchestrator

This is a 2026-10-02 receipt for stream E-PT8 on branch `claude/gcp-fp-e-pt8`,
built on `claude/gcp-fp-d-pt5a` at `2e279c66` with `f8a8620d` (D-PT4X's
migrations promoted as primary `0066` and `0067`) merged in. It records
**local, synthetic** evidence only: one macOS arm64 workstation, Node 26.2.0
and local PostgreSQL 17.10. Nothing was deployed or migrated in any GCP or
Cloudflare project, no `gcloud`, `wrangler` or push ran, no production data
was read and no real secret was handled. Nothing is merged.

## Behaviour proven

- **One disposition per sealed table.** 163 ingestion tables (the d43c8f92
  catalog's 162 plus `d1_storage_migrations`) and 5 deletion-ledger tables,
  equal to the synthetic seal's catalog in both directions. PT-3, D-PT5A and
  D-PT4X tokens are taken from their exports, not restated. After the run,
  every sealed table holds exactly one complete table receipt with exactly its
  token and stage.
- **Deletion-digest exclusion count (P6).** Tombstone digests, projection
  sha256, participants by state and matches; a planted tombstone refuses
  `CUTOVER_ERASED_PARTICIPANT_PRESENT`, a projection from another ledger
  refuses `CUTOVER_PROJECTION_SEAL_MISMATCH`. The PostgreSQL-side do-not-restore
  re-check runs again in post-import.
- **Identity pin (P8).** Stdin only; the fingerprint equals the W2-SEAL vectors
  and the Worker's domain literal; a mismatch, a wrong deployment label, a
  short secret and `latest` are each refused. The pin must also name the
  secret and numeric version that the committed production desired state
  mounts (`IDENTITY_LINK_SECRET`); an unpinned mount and another version are
  refused.
- **Parity sample.** Independent SQLite and PostgreSQL SQL per sampled owner
  over M1, M2, H1, H2, E1 and E2; zero mismatches on the synthetic seal.
- **Finalize order.** The staging drop and the C-IPR frozen-read load run in
  post-import, before `verified` and so before `markLive`; PT-1 refuses the
  drop after `verified` (asserted). Then flip-1 evidence after `verified`,
  `restoreSealedCollectionControls`, flip-2 evidence after the recorded
  release instant, the flip gate (staging-drop readback, frozen read,
  `assertFlipReady`, Sparkle nonces), and `markLive`. After live a
  transfer-schema insert raises `TRANSFER_TARGET_LIVE`.
- **Dry run, tokens, resumability.** Every protected step is dry by default
  and needs its exact token. A run killed after each of its 32 committed steps
  (including between writing `post-import.json` and committing the stage)
  and resumed ends with table and stage receipts equal to a clean run on a
  second target, and an equal post-import receipt body.
- **Negative tests.** Each preflight check (P1 to P12), the dry run, a wrong
  token, both locks, every out-of-order finalize step (an exhaustive 392-case
  state matrix in the check, and on PostgreSQL release, gate and mark-live
  before `verified` and before the release), stale and tampered flip
  evidence, a foreign transfer-role member, a pending-object conflict in
  post-import, abandon and the spent target. Every preflight refusal leaves
  the target without a run.

## Decisions and deviations

- **Authorization token.** The design's `--confirm=<preflight sha>` and
  `--confirm=<flip-gate sha>` are replaced by one step-bound token per
  protected step (sha256 of the step, seal, contract, inputs file and the
  step's evidence, which includes those digests).
- **Inputs file.** The design's per-command flags are a closed
  `pt8-inputs.json` in the owner directory; its sha256 is in every token.
- **Connection.** A local Unix socket only (a Cloud SQL Auth Proxy with
  automatic IAM authentication in production). The production transfer
  identity is not provisioned (PT8-I).
- **Production comparisons.** The rehearsal-only `compareFastpath*` helpers
  refuse any non-rehearsal schema, so owner-revision and public-source-owner
  parity are re-implemented inside the transfer handle's read-only
  transaction, with the same canonical lines.
- **Erased owner links** are a refusal (`CUTOVER_OWNER_LINK_ERASED`, P5): a
  link marked erased whose participant row still exists is an unfinished
  erasure, because the link cascades away with its participant.
- **`storage_legacy_event_sources`** must be empty: the design's "any, provably
  applied" proof is not built, so the stricter rule applies.
- **Round 5** dispositions: admin metric history `mapped:admin-metrics-history`,
  aggregate exclusions `imported:community-aggregate-exclusions` (D-PT4X).
- **Correction runtime in the pre-fence gate.** Not moved: the Q-1 corpus
  carries an `active` runtime, so the move would block every pre-fence run
  until OWN-3 answers the correction-runtime question.
- **Identity key version.** The design takes `keyVersion` from the committed
  desired state, but that file has no such field (the production value,
  `production-v1`, is `PRODUCTION_VARS` in
  `cloud-run/postgres-production-configuration.mjs`). P8 still compares it with
  the owner-typed `expectedIdentityKeyVersion`. The secret name and version
  are bound to the committed desired state.
- **Desired state read as data.** C-INFRA's validator module imports the Cloud
  SQL connector, so the orchestrator reads the committed file directly
  (schema, environment, project, the closed `IDENTITY_LINK_SECRET` mount). The
  check pins the schema literal, the file path and `SCHEDULED_JOB_NAMES`.
  Until the production desired state names a project and a numeric mount
  version, preflight refuses (`CUTOVER_DESIRED_STATE_INVALID`, then
  `CUTOVER_IDENTITY_LINK_MOUNT_UNPINNED`). That is intended.

## Open issues

- The correction-runtime owner question (OWN-3): if production is `active`,
  preflight refuses `CUTOVER_CORRECTION_RUNTIME_ACTIVE`.
- P11 checks a scheduler probe receipt (exactly the managed triggers, all
  `PAUSED`, no alert, after the fence, under 6 h old at preflight and again
  at each `run`). It cannot see a running Job execution. A single long `run`
  invocation is not re-checked part way through.
- The release instant comes from the database clock, and flip-2's
  `verifiedAt` from the operator's clock. If the operator's clock runs fast
  by d ms, flip-2 evidence taken up to d ms before the release is accepted.
  The flip-1 check against `verified_at` has the same property.
- The parity sample's E1 covers record counts per owner-day and family; token
  sums are compared only for v0.2 records (E2). Typed v1/v1.1 token sums are not
  sampled.
- `CUTOVER_TYPED_IDENTITY_HEADROOM_INVALID` is the only orchestrator code with
  no negative test. Breaking it needs a different `typed_telemetry_restart_identities()`.
- The branch is based on `claude/gcp-fp-d-pt5a` at `2e279c66`; that branch has
  since moved (`0189148f`, review fixes). The integrator reconciles.
- The production transfer identity, its SET-only memberships and the proxy
  (PT8-I) are not provisioned; nothing has run against a real seal or Cloud SQL.
