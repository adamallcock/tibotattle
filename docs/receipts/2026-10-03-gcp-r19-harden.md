## Choices worth reviewing

- **The fence receipt is also a new verify-unchanged input.** The seal
  manifest's fence summary covers only the sealed roles, so the analytics pin
  is read from the receipt itself, at the digest the seal pins, exactly as the
  capture and the admin history export read it.
- **A bookmark-only role, not the floor role.** The floor role admits its one
  SELECT; verify-unchanged needs none, so `analytics-bookmark` admits nothing.
  It reads only time-travel bookmarks, so it is read-only by construction.
- **Read errors keep their own code.** A failed analytics bookmark read
  surfaces as the transport's `CUTOVER_REMOTE_RESPONSE_INVALID`, not as
  `CUTOVER_ANALYTICS_CHANGED_AFTER_FENCE`: a failed read is not evidence of a
  publication. Both refuse.
- **Flip evidence v2.** Evidence is produced and consumed inside one window;
  no v1 file exists outside tests, and a v1 file is refused rather than
  accepted without the analytics entry.
- **(d) layering.** In production the floor refusal already covered any run
  without a floor, so the new gate changes behaviour only in naming the
  first-run state precisely and in holding if the floor rule is ever relaxed.
  A production first run with the floor but without the frozen read still
  runs (the flip gate's `CUTOVER_INTERIM_READ_NOT_LOADED` keeps that state
  from going live). Read literally, "without the frozen row or the floor"
  could also mean refusing when either is missing; the computed brief says
  "neither ... nor", and that is what is built.
- **The offline check does not compare against the frozen export.** P16 also
  refuses `REVISION_FLOOR_BELOW_FROZEN_EXPORT`; the offline check would need
  the export and its four recorded facts, which (b) did not ask for. The
  runbook says so.
