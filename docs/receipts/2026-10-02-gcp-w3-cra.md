## What landed

### A1: `cloud-run/postgres-production-registry.mjs` (CR-6)

- `PRODUCTION_ROUTE_TABLE`: every one of the 51 `d43c8f92` production routes
  in Worker order (`workerOrder` = its position in the policy) with a class:
  `scope` (21, this item's ported scope), `od-cr-1` (9, the contested routes),
  `od-cr-2` (19, unported) and `root` (2). The check pins the ids, the order,
  the counts, the policy digest, the brief's lists and the edge-test served
  set (`EDGE_TEST_SERVED_ROUTE_IDS` = scope without `ready` plus the nine).
- `createProductionRouteRegistry({routePolicy, handlers, portedRouteIds})`:
  the ported set is **injected with no default (OD-CR-1)**. It must contain
  all 21 scope routes and may add any subset of the nine; it can never
  contain an `od-cr-2` route (porting one needs the OD-CR-2 answer and a
  reviewed class change first). The handler map is snapshotted. It returns a
  frozen registry: `resolve(routeId)`, `portedRouteIds`, `portedPathnames`
  (both in Worker order), `unportedRouteIds` (sorted), `rootRouteIds` and
  `coverage: "complete"`. `isProductionRouteRegistry` accepts only issued
  registries.
- Closed refusals (`PRODUCTION_ROUTE_REGISTRY_CODES`, every one exercised):
  `COVERAGE_INCOMPLETE` (50 or 52 routes, a duplicate id or pathname, a
  malformed entry, a ported id outside the policy such as the v1.2
  effective-page path), `PARITY_BASIS_DRIFT` (51 routes but not the pinned
  ones in the pinned order), `PORTED_SET_INVALID` (missing, not a list,
  duplicates), `ROOT_CLAIMED` (a root route ported or given a handler),
  `PORT_UNDECIDED` (each of the 19), `SCOPE_INCOMPLETE` (each of the 21),
  `HANDLERS_INVALID`, `HANDLER_UNEXPECTED` (an unported or contested id, a
  pathname, any other key), `HANDLER_MISSING` and `UNKNOWN`.
- **Online erasure is retired** (`RETIRED_ONLINE_ERASURE_SURFACES`):
  `DELETE /api/v1/me` is outside the policy and answers 404 `NOT_FOUND`
  (`unknown_api`); `admin_action` stays `od-cr-2`, and a later port omits its
  `participantErasure` branch. The check asserts no route id or pathname names
  erasure or deletion.

### A2: `cloud-run/postgres-host-dispatch.mjs` (CR-6)

`createProductionRequestHandler` follows `handleRequest` step by step:
edge request id and host kind (a verifier has neither: fresh id, apex); the
www 308; the admin host under the injected **OD-CR-3** policy (`refuse`:
503 `POSTGRES_ROUTE_NOT_PORTED` before anything; `chokepoint`: the Worker's
`verifyAdminAccessAssertion` and `authorizeAdminEmail`, then the generic
pipeline, admin ids carrying the identity key in their context); the public
host's admin paths and six admin ids as 404; the registry method envelope
(405 with `Allow` joined by `, `); `community_daily` 503
`PUBLICATION_DISABLED` unlogged; `unknown_api` 404; assets as the JSON 404 of
EP-6's `edgeServedAssets`; root routes 404; unported routes the closed
503 `POSTGRES_ROUTE_NOT_PORTED` with the injected **OD-CR-6(iv)**
`retry-after` (or none); ported routes inside
`requestContextStore.dispatch` with `{requestId, routeId}`, `community_daily`
behind the storage gate and its 200 passed through, everything else
`no-store`. A non-`ApiError` is 500 `INTERNAL_ERROR`. The migration barrier is
deliberately absent.

Every construction input is required except the logger, and each refusal is a
closed code (`ORIGIN_HANDLER_CONFIGURATION_CODES`), including
`PRODUCTION_HANDLER_ADMIN_HOST_POLICY_UNDECIDED` and
`PRODUCTION_HANDLER_UNPORTED_RETRY_AFTER_UNDECIDED`. `unportedRetryAfterSeconds`
(**OD-CR-6(iv), no default**) is `null`, which sends no `retry-after` as the
base's fail-closed unported answers do, or a positive safe integer, which
sends that many seconds (the brief proposes 60). An omitted key, `0`, a
fraction, a string or any other value refuses to build. The registry must be an
issued one over the Worker's own `WORKER_ROUTE_POLICY` object, so the
handler matches with `matchWorkerRoute` and never duplicates it.

Logging: one JSON line with exactly `ORIGIN_REQUEST_LOG_FIELDS`
(`level, severity, event, requestId, method, routeClass, code, status`), the
Worker's catch classification (`classifyOriginOutcome`), methods outside the
seven known ones as `OTHER`. A family error response is classified from a
bounded (8 KiB, JSON only) clone of its body, so the caller still receives the
whole body. The check proves that no injected address, query, cookie,
authorization or Access value reaches a line or a diagnostic event.

`createPrivateTestRequestHandler` is the loopback pipeline: another origin or
anything not ported goes to the fallback; a ported route goes to its family.

## Where the brief and the code differ

1. **Contract modules split out.** The validators live in import-free
   `src/postgres-*-contract.ts` files: the smoke runs under plain Node, the
   Worker `src` modules use extension-less imports, and `tsconfig.json` does
   not allow `.ts` import extensions. `postgres-readiness.ts` refuses to load
   if the contract's 7 200 000 ms ever differs from
   `BACKEND_LIFECYCLE_STALE_MILLISECONDS`.
2. **Diagnostics follow the Worker, not the brief's wording.** The brief
   records only error-level 5xx; the Worker calls `recordDiagnosticError`
   for every `request_failed`, whose writer keeps only sampled 5xx, so a
   containment 503 is recorded there. The handler offers every
   `request_failed` event to the injected recorder
   (`recordPostgresDiagnosticError` samples the same way) except the origin's
   own `POSTGRES_ROUTE_NOT_PORTED`, which has no Worker counterpart and would
   otherwise fill the 256-row table.
3. **The RD-2 not-ready DTO is not logged.** `handleReady` returns it without
   throwing; a literal ">= 400 is logged" rule would log every readiness
   probe as an `UNCLASSIFIED` error. A ready answer that carries an error
   envelope is logged as usual.
4. **The asset 404 is rendered in the handler** with the handler's request id.
   It is byte-identical to `edgeServedAssets` behind EP-6 (asserted), and it
   cannot disagree with the injected request-context accessor.
5. **Registry validation is stricter than the brief:** the ported set must
   cover the 21 scope routes, may not hold an `od-cr-2` route, and the 51
   routes must be the pinned ones in the pinned order. Four codes are added:
   `PARITY_BASIS_DRIFT`, `PORTED_SET_INVALID`, `PORT_UNDECIDED`,
   `SCOPE_INCOMPLETE` (plus `HANDLERS_INVALID` and `UNKNOWN`).
6. **The www 308 keeps Worker parity:** no `cache-control`, as
   `Response.redirect` in the Worker. EP-6 never rebuilds on www, so it is
   unreachable behind the edge.
7. **Admin route ids come from the policy's `admin` authority**, pinned equal
   to `EDGE_ADMIN_API_ROUTE_IDS`, rather than a second hand-written list.
   Under `chokepoint` they go through the generic method envelope, so a wrong
   method is 405 after the chokepoint, as in the Worker.
8. **`isEdgeOriginBoundaryRefusal` is re-exported** from
   `origin-edge-test-mode.mjs`. It reads the origin marker on EP-6's response,
   and `test/edge-request-header-allowlist.spec.ts` reviews that read per file;
   phase B moves the function together with its ratchet entry. The critic's
   "reviewed entry for content-type" (host gap 2) is not needed and not
   possible: `content-type` is a forwarded request header class, and the
   ratchet refuses a response entry for a request-class name.
9. **Revision tags only on an https origin**, so the loopback modes never
   accept a tagged Host.
10. **The smoke takes `--upstream-origin`.** OPS-2's RolloutTarget has no
    service URL; OPS-10's roll reads it with `gcloud run services describe`,
    which is a cloud read this script does not make.
11. **The unported `retry-after` is injected, not the brief's constant 60.**
    The brief's A2 freezes 60, but OD-CR-6(iv) leaves it open and the base's
    fail-closed unported answers carry none, so the handler takes it as a
    required parameter (see A2). The 503 status matches the base's
    fail-closed answers; the code `POSTGRES_ROUTE_NOT_PORTED` is the brief's
    production name.

## Decisions that block the merge

- **OD-CR-1** (ported list): the registry has no default ported set.
- **OD-CR-3** (admin host): the handler has no default policy.
- **OD-CR-4** (readiness meaning): the builder and the smoke have no default.
- **OD-CR-5** (health capability flags): the builder has no default.
- **OD-CR-6(iv)** (unported `retry-after`): the handler takes
  `unportedRetryAfterSeconds` with no default (`null` for none, or seconds);
  the phase-B composition cannot build the handler until the owner picks one.
  The owner's answer is a one-argument diff at the composition root.
- **OD-CR-6(v)** (asset JSON 404): the handler answers an asset with the
  JSON 404 of EP-6's current `edgeServedAssets`, byte-identical behind EP-6;
  the owner accepts it or chooses another answer.
- **OD-CR-9** (parity basis): the table and DTOs are pinned to the unverified
