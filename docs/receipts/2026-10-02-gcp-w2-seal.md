# GCP W2-SEAL seal, projections and identity importer

This is a 2026-10-02 receipt for branch `claude/gcp-fp-w2-seal`, built on
`45afdf63` (`claude/gcp-fp-edge`). It records **local, synthetic** evidence
only: one macOS arm64 workstation, Node 26.2.0 for the scripts and checks,
vitest 4.1.11, and a local PostgreSQL 17 cluster on a private Unix socket.
No Cloudflare or Google Cloud resource was read or written, no Wrangler or
gcloud command ran, and no production data was used. Every D1 source is the
Q-1 synthetic corpus plus synthetic rows; every secret is a fixture constant.

## What landed

### PT-2-lite (`apps/worker/scripts/cutover-source-*.mjs`)

- **Sources.** Only the ingestion D1 (`USAGE_MONITOR_DB`) and the
  deletion-ledger D1 (`DELETION_LEDGER`) from an owner `0600` inventory
  (`tibotattle-cutover-inventory-v1`). Any other role or D1 id is
  `CUTOVER_SOURCE_NOT_ALLOWED`; the analytics D1 is never sealed.
- **Expected ledgers** are read from git objects at
  `inventory.expectedSourceCommit` (never the working tree), with bare names:
  `d1_migrations` names and `d1_storage_migrations` (name, sha256 of the file
  bytes). Directory-prefixed names are `CUTOVER_LEDGER_NAME_NOT_BARE`.
- **Seal.** Dry run by default; a remote run needs `--execute --remote
  --owner-read-only`. Every remote read goes through a guarded transport that
  admits only inventory sources and one `SELECT` with no separator, comment or
  mutation keyword (`CUTOVER_REMOTE_SQL_NOT_SELECT`). B0 must equal the EP-8
  fence bookmark and B1 must equal B0 (`CUTOVER_SOURCE_BOOKMARK_DRIFT`). The
  export is an injected spawn with piped, discarded stdio, umask `077`, a
  pre-created `0600` dump and Wrangler log in a `0700` owner directory outside
  the repository and the agent scratchpad; the log is deleted after the
  export. A closed signed-URL scan of the dump raises
  `CUTOVER_SECRET_IN_OUTPUT`. The dump is rebuilt with `node:sqlite` under a
  closed statement grammar (provider tables in the export are
  `CUTOVER_EXPORT_PROVIDER_TABLE`), copied with `VACUUM INTO` to one `0400`
  file, and deleted. Acceptance requires `integrity_check` ok, schema equal to
  the remote schema under one predicate (`sqlite_*` and the exact rows of
  `src/d1-provider-schema.json` excluded), ledgers equal to remote and
  expected, `sqlite_sequence` equal to remote, and per-table `count(*)`,
  text/blob byte length sum, first-key min and max and REAL `total()` equal to
  the remote aggregates. Key minima and maxima stay in memory; the manifest
  holds per-table aggregate digests only. On any failure every artifact of the
  run is deleted and no manifest is written. That includes the default
  Wrangler transport's pinned `<role>.wrangler.json` configs (account id, D1
  name and id, `0600`): the transport tracks each config it writes and is
  disposed on every path, and a config it did not write is
  `CUTOVER_OUTPUT_EXISTS` and is left alone.
- **Manifest** `tibotattle-cutover-seal-v1`: its `sealId` is the sha256 of the
  canonical body, `createdAt` included, and is the PT-1 seal id.
- **verify-fence** reads the EP-8 verify receipt with
  `readCloudflareWriterFenceReceipt` (fenced Worker, empty schedules, paused
  delivery, quiet window, zero writes, unreleased) and binds its ingestion and
  deletion-ledger bookmarks to the inventory ids by digest
  (`CUTOVER_FENCE_SOURCE_MISMATCH`). The barrier proof is a closed file
  (`tibotattle-cutover-barrier-proof-v1`): `GET /api/health` barrier health
  with `deployment.sourceCommit` equal to the receipt's commit, and one
  dynamic probe answering `503 MUTATION_BARRIER_ACTIVE` with `no-store` and
  `retry-after: 300`, observed after the fence was applied. A receipt whose
  `productionWorker.sourceCommit` is null (EP-8 records null when the live
  `DEPLOYMENT_SOURCE_COMMIT` binding is absent or invalid) binds no proof
  and is refused (`CUTOVER_BARRIER_PROOF_INVALID`, check `source-commit`).
- **verify-unchanged** re-reads every bookmark, the schema digest and every
  aggregate through the transport, re-hashes the sealed files, and writes
  `flip-evidence.json` (`0400`, never overwritten) with its sha256, or
  `CUTOVER_SOURCE_CHANGED_AFTER_SEAL`. Like the seal, it accepts an injected
  `spawn`, `cliPath` and `environment` for the default transport and
  disposes that transport's configs, so the owner directory then holds only
  `flip-evidence.json`, or nothing.
- **Projections.** The journal projection has the existing
  ingestion-journal importer's exact layout (`0400`, sha256) and is accepted by
  `createSealedSqliteIngestionJournalSource`. The deletion-digest projection
  holds only the sorted `deletion_tombstones.participant_digest` values,
  `0400`, with its sha256: the do-not-restore seed (D2). The intersection
  (`countSealedParticipantDeletionMatches`, gate form
  `assertNoSealedParticipantDeletionMatches`) hashes every sealed
  participant, whatever its state, in memory with the Worker's
  `participantDeletionDigest` domain (pinned against
  `src/participant-deletion-digest.ts`) and reports counts only: participants,
  participants per state (`active`, `deleting`; any other value is
  `CUTOVER_PROJECTION_INVALID`) and matches. A nonzero match is
  `CUTOVER_ERASED_PARTICIPANT_PRESENT`, the code the PT-8 brief names.

### PT-3 (`apps/worker/scripts/postgres-identity-authority-transfer.mjs`)

- The `identity-authority` stage on PT-1's handle, under `SET LOCAL ROLE`, with
  the sealed file hashed before, during and after. It requires an import
  transfer session (`storage_journal_transfer_session()`), so the IAM login is
  a non-escalating `SET` member of `tibotattle_source_transfer`.
- The frozen COLUMN_MAP reuses T-1's reviewed column specs through additive
  exports of `postgres-fastpath-identity-copy.mjs` (behaviour and allowlist pin
  unchanged) and adds the reviewed tables in the same type vocabulary.
  Credential and rotation hashes are imported. The frozen order covers 35
  tables in four groups and is asserted against the target's foreign keys.
- Every refusal runs before the first write: column closure
  (`CUTOVER_COLUMN_UNMAPPED`), `sqlite_sequence` against the frozen
  COUNTER_MAPPING (`CUTOVER_COUNTER_UNMAPPED`), every sealed value
  (`CUTOVER_SOURCE_VALUE_INVALID`), the identity-link pin
  (`CUTOVER_IDENTITY_LINK_SECRET_MISMATCH`), erasure quiescence (every
  sealed participant `active` with a NULL `deletion_session_id`, else
  `CUTOVER_PARTICIPANT_ERASURE_PENDING`), the public-source bootstrap
  (`CUTOVER_PUBLIC_SOURCE_BOOTSTRAP_INCOMPLETE`), the accountless authority
  chain (`CUTOVER_ACCOUNTLESS_AUTHORITY_CHAIN_INVALID`), the transfer session,
  trigger-policy coverage and target layout. Controls that cannot be degraded
  roll the stage-start transaction back.
- Pages hold at most 256 rows and 4 MiB. A page's transaction writes a
  checkpoint carrying the row count and prefix chain (never a key) and the
  rows, with the reviewed triggers suppressed for that page only. A killed run
  replays the sealed prefix, requires the same chain and row count, and
  resumes. A table completes only when its target digest equals the sealed
  digest. Then `applyIdentityHighWater` and the instant round trips run and
  the stage receipt completes. A replay of a finished stage reproduces the
  receipt without writing: it asserts the controls are still degraded at the
  sealed revision instead of degrading them again and leaves the bootstrap
  row alone, so no application row, receipt or checkpoint gets a new row
  version.
- Not imported: `identity_reenrollment_cooldowns` (D2), every deletion-ledger
  table and the `accountless_public_history_*` retention markers. Revoked
  ledger, owner, grant and device rows carry over verbatim.
- Staged `apps/worker/postgres/staged-migrations/primary/0063_enrollment_grants_erased_redeemer.sql`
  (the lead renumbers it at landing): it replaces primary 0015's shape CHECK
  and admits a redeemed grant with a NULL redeemer only as a transfer-session
  `INSERT`. Every live `INSERT` or `UPDATE` of that shape, including the
  `ON DELETE SET NULL` action, is still refused with `23514`.

## Where the brief and the code differ

The code and the owner decisions were followed in each case.

1. **Bootstrap cursors.** The brief says the sealed bootstrap singleton
   replaces the seeded row verbatim. Primary `0053` refuses non-empty cursors
   and directs an importer to write `''` for a completed D1 row, so T-1's rule
   is reused: policy and `completed` verbatim, cursors `''`.
2. **Ledger layout.** Which directories each production ledger holds is not
   recorded anywhere in the repository. The inventory declares it, and every
   ingestion directory must appear in exactly one ledger. The Q-1 oracle
   applied all six directories through one Wrangler ledger; the check proves
   the bare-name expected ledger at `d43c8f92` reproduces its 90 rows exactly.
   *Superseded in part (2026-10-02):* production ingestion carries the
   restore-era ledger, which no fresh-chain layout accepts; see
   [the restore-base layout receipt](./2026-10-02-gcp-int-c-seal-restore-base.md).
3. **Identity-link pin.** The importer takes the configured
   `{keyVersion, secretFingerprint}` and never the secret. A sealed source
   without a pin row is refused like a mismatch.
4. **Seeded rows.** `telemetry_transport_formats` is merged: each sealed row
   must match a seeded (schema version, rank) pair and only `lifecycle` is
   updated. PostgreSQL's extra v1.2 seed row is left as seeded (D1 has none at
   `d43c8f92`; T-2 owns the v1.2 runtime). `accountless_enrollment_issuance`
   and `github_distribution_sync_state` replace their seeds.
5. **Derived rows.** `participant_input_created` is suppressed and replaced
   by a set-based `input_versions` insert at revision 0 in the same page
   (PostgreSQL-only state; D1 has no such table).
6. **Floor rollbacks.** `telemetry_transport_rollback_owner_only` is
   suppressed on import: it admits only a started audit whose floor still
   sits at the rollback's revision, which completed history never satisfies.
   The foreign key to `admin_action_audit` still holds, so audit rows import
   first.
7. **Target-missing tables.** `telemetry_performance_device_capabilities` and
   `accountless_telemetry_performance_authorizations` have no promoted
   PostgreSQL table (PF-1 is unpromoted). They are counted and digested in the
   stage result, not imported, and not given a table receipt; PT-8-lite or an
   owner decision on performance routes must dispose of them.
8. **Counters.** `sqlite_sequence.seq` is untyped; an integral REAL value is
   accepted as a counter (the Q-1 rebuild stores some as REAL).
9. **R2.** verify-unchanged re-reads D1 bookmarks and aggregates only; the R2
   digest belongs to the reduced PT-7 copy.
10. **Interim ledger.** PT-1 at `45afdf63` still requires a ledger database,
    so the specs register an interim `w2_seal_ledger` schema in a second
    database on the same cluster; nothing is written to it.

What the checks and specs prove:

- **Default transport.** A synthetic CLI stand-in (never executed) and an
  injected spawn drive the real transport and export code. The seal then
  leaves only the two sealed files and the manifest, and its per-source
  schema, aggregate, sequence and ledger digests equal an injected-transport
  seal's, so Wrangler's JSON envelope yields the same facts. B0 drift, B1
  drift after the export, and drift on the second source each leave an empty
  owner directory. A pre-existing config refuses with `CUTOVER_OUTPUT_EXISTS`
  before any call and is left in place. verify-unchanged leaves only
  `flip-evidence.json`, or nothing on drift. The transport's `dispose()`
  removes both configs it wrote.
- **Seal.** A fake Wrangler prints a signed URL on stdout, stderr and its log.
  After the seal, the owner directory holds only the two sealed files and the
  manifest, all `0400`. No file and no result contains the URL. The dump was
  `0600` when the child opened it and after it wrote. An injected echo into
  the export trips `CUTOVER_SECRET_IN_OUTPUT` and leaves an empty directory.
  These each refuse with their own code: drift in row count, length sum, key
  and REAL total, drift in schema, `sqlite_sequence` and ledgers, B0 and B1
  drift, canonical ledger names, an unknown `_cf_` table, a provider table or
  a disallowed statement in the export, a non-allowlisted D1, and a mutation
  sent to the guarded transport, which never reaches it.
- **Fence.** verify-fence passes only for a valid, unreleased, fenced EP-8
  receipt for the inventory's D1s plus a closed barrier proof; every tested
  receipt and proof variant refuses, including a receipt with a null commit
  against proofs from three different commits. verify-unchanged writes evidence
  only when every bookmark, schema and aggregate equals the seal; a moved
  bookmark, a changed aggregate or schema, or a changed sealed file refuses and
  writes nothing.
- **Projections.** The digest projection is exactly the synthetic tombstone
  digests, sorted, `0400`, with a matching sha256, and carries no cooldown or
  erasure-job value. The intersection is 0 on the clean corpus and 1 with a
  planted active participant. A participant forged to `deleting` with a
  deletion fence (an interrupted erasure) and a recorded tombstone counts 1
  and refuses with `CUTOVER_ERASED_PARTICIPANT_PRESENT`; without the
  tombstone it counts 0 matches and 1 `deleting`. A state outside the D1
  CHECK refuses. No participant id appears in any output.
- **Importer.** Nine variants refuse before any write: a wrong secret, a wrong
  key version, an incomplete bootstrap, a foreign bootstrap policy, a broken
  chain, an unmapped counter, an unmapped column, a participant mid-erasure

  database-free check also refuses a `deleting` participant with a NULL fence
  and an `active` one still carrying a fence. Each
  run is then abandoned, and the next fresh open proves the tables empty. A run

  receipt and checkpoint at the same `xmin` and the controls at the same

## Open issues and owner inputs

- The real Wrangler export, query and `time-travel info --json` paths are
  exercised only through an injected spawn and a synthetic CLI stand-in;
  their output shapes are unverified against the provider. Whether a real D1 export includes `_cf_` tables, `sqlite_sequence`
  rows or REAL formatting that changes REAL totals is unverified; each would
  refuse rather than pass.
- The owner must supply the inventory (D1 ids, names, ledger layout, the
  production source commit), the EP-8 receipt and the barrier proof, and the
  configured identity-link pin.
- Remote aggregates scan every table of the ingestion D1 inside the outage
  window; their duration on production volumes is unmeasured.
- The importer refuses a target without the `0063` trigger (the trigger policy
  names it), so `0063` must land before PT-3 runs.
- PF-1 performance-consent tables have no target (item 7 above).
- Full sealed-table dispositions, the history parity sample and the
  identity-pin check of the orchestrator remain PT-8-lite's.
- A participant left `deleting` (or with a deletion fence) is refused by PT-3
  after the seal, inside the outage window. The fenced Worker cannot finish
  that erasure, so the owner must release the fence, finish it, re-fence and
  re-seal. A read-only pre-fence query for such participants would find this
  before the outage; it is not built.

## Review fixes

Four findings from the 2026-10-02 review of `24801397` were verified against
the code and fixed; none was rejected.

1. **High: a `deleting` participant escaped the do-not-restore check.** The
   intersection read only `state = 'active'`, while PT-3 imports every
   participant. The Worker marks a participant `deleting`, records its
   tombstone and can still fail (or be fenced) before the rows are gone, so a
   tombstoned participant could be imported with its sessions and devices.
   The intersection now hashes every participant and reports counts per
   state. PT-3 refuses, before any write, any participant that is not
   `active` or still has a `deletion_session_id`
   (`CUTOVER_PARTICIPANT_ERASURE_PENDING`). PostgreSQL has no online erasure
   (SIMP-1) and the PT-8 brief requires erasure quiescence, so no disposition
   override was added: the cure is to finish the erasure on Cloudflare and
   re-seal. The intersection code is now `CUTOVER_ERASED_PARTICIPANT_PRESENT`
   (the PT-8 brief's name) rather than `CUTOVER_ACTIVE_PARTICIPANT_DELETED`,
   and the functions are renamed to match.
2. **Low: a null EP-8 commit accepted any barrier proof.** verify-fence now
   requires a 40-hex receipt commit equal to the proof's. A Worker without a
   valid `DEPLOYMENT_SOURCE_COMMIT` answers barrier health with `503` and no
   commit, so no valid proof could come from it anyway.
3. **Low: the default transport left `<role>.wrangler.json` behind.** See the
   seal and verify-unchanged bullets above. verify-unchanged also gained the
   `spawn`, `cliPath` and `environment` options, so the default transport is
   now tested offline.
4. **Low: a replay rewrote `collection_controls`.** The stage start now
   asserts the degraded controls and skips the bootstrap update when the
   stage receipt is complete; the replay test pins every row version.
