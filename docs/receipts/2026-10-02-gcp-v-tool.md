# GCP vendoring generator takes the production commit

This is a 2026-10-02 receipt for stream V-TOOL (checklist item K-VENDOR, the
tool half). Branch `claude/gcp-fp-v-tool` starts at `afd865a0`, the head of
`claude/gcp-fastpath-final`. It holds two commits: `efd25c43`, the generator and
its first check, and a review-round commit that fixes the defects listed in
[Review round](#review-round). The branch is not merged into any other branch.

The evidence is **local and synthetic**. It ran on one macOS arm64 workstation
under Node 26.2.0, while build wave 4 was running on the same machine, so the
timings below are loaded timings. Nothing was deployed, built in Cloud Build,
pushed, or read from a GCP or Cloudflare project. The only inputs were git
objects already in the repository.

## Claim boundary

Proven here:

- `apps/worker/scripts/vendor-analytics-kernels.mjs` takes the production
  commit as `--commit=<40-hex>` and locates its export patches by symbol.
- Before it writes anything, the generator proves the tree it is about to write
  on its own: every entry bundles from the written files alone, the closure those
  files give equals the extraction's, the bundled facade loads, and `tsc` accepts
  the facade. A refusal leaves existing output untouched.
- At `d43c8f92` it reproduces the committed `vendor/analytics-d43c8f92` tree
  and the `analytics-v2-test/kernel-parity` specs byte for byte.
- `--report` answers "can this commit be vendored with this facade as it
  stands" by doing what the generator does, in a temporary directory.
- Its refusals are tested, and deliberately weakened generators fail them.

Not proven, and not done here:

- A vendored tree for any other commit is **not** committed. The only runs at
  other commits were into scratch directories, and their output was not kept.
- `entry.ts`, the `PARITY_SPECS` list and the other reviewed lists are still
  code constants, written for `d43c8f92`. See [Hand-offs](#hand-offs).
- The second half of K-VENDOR, generating the GCP-only vocabularies (70 dates,
  refusal reasons, band ids) from the vendored kernel, is not part of this
  change.
- `origin/main` (`396204d3`) is not the production commit. The owner's
  `GET /api/health` still has to supply it.

## The tool

```text
node scripts/vendor-analytics-kernels.mjs [--commit=<40-hex>] [--out-root=<dir>] [--authored-from=<vendor dir>]
node scripts/vendor-analytics-kernels.mjs --report [--commit=<40-hex>] [--reference=<MANIFEST.json>]
```

- **Commit.** It must be a full 40-hex id, case folded. Abbreviations, refs
  and tags are refused, because they move. The id must resolve in this
  repository to that same id as a commit. A tree id, an annotated tag id or an
  absent id is refused before anything is written. With no `--commit` the
  default is `d43c8f92`, so the existing workflow is unchanged.
- **Directories.** The vendor directory is `vendor/analytics-<first 8 hex>`.
  The parity specs of `d43c8f92` keep `analytics-v2-test/kernel-parity`; any
  other commit gets `analytics-v2-test/kernel-parity-<8 hex>`, so two vendored
  revisions never share a parity directory. A vendor directory whose manifest
  names a different commit is refused and left untouched.
- **Patches by symbol.** Each patch is `{ path, symbol, declaration }` with
  `declaration` one of `function`, `async function` or `const`. The locator
  masks comments, strings, template literals and regex literals, then requires
  exactly one declaration of the symbol in the file. The statuses are closed:

  | Status | Meaning | Outcome |
  |---|---|---|
  | `apply` | One column-0 declaration of the named kind, not yet exported | Patched |
  | `already-exported` | The same, and the commit already writes `export` | Left alone; recorded in the manifest as `exportsAlreadyPresent` |
  | `missing` | No declaration | Refused |
  | `ambiguous` | Overloads, shadowing, a named function expression | Refused |
  | `not-top-level` | Nested, `export default`, `declare`, or otherwise not at column 0 | Refused |
  | `unsupported` | `let`, `var`, `class`, `enum`, `namespace` or a generator | Refused |
  | `kind-changed` | A different supported kind than the patch names | Refused |
  | `export-clause` | An `export { }` or `export * as` also names it | Refused |
  | `unlexable` | The lexer cannot close a comment, string or template | Refused |
  | `file-missing` | The file is not in the commit | Refused |

  A refusal names the first failure in its code (`EXPORT_SYMBOL_<STATUS>`) and
  lists every failing patch in its detail. The lexer tells a regex from a
  division by the previous token. A `/` after a `)` that closes an `if`, `while`
  or `for` header, or after a `}`, starts a regex; after any other `)` it is a
  division.
- **Parser confirmation.** After locating, esbuild reads each file before and
  after patching. A patch must add exactly its own export, and no other export
  may appear or disappear. This guards the lexer, and it catches a `const`
  statement that declares two bindings. The edit stays one `export ` token per
  patch, and the byte length is checked.
- **Closure.** The files to vendor are every module esbuild **parsed** for the
  facade, the website normalizer and the parity specs, found by walking
  `metafile.inputs[*].imports` from each entry. It is not the bundle's
  `outputs[].inputs`, which leaves out a module that tree-shaking removed even
  though the vendored files still import it. Imports TypeScript erases are never
  resolved by esbuild and stay out, so only genuine type-only imports leave the
  closure.
- **Standalone verification.** The generator stages exactly the files it would
  write in a temporary directory and, from those files alone: bundles every
  entry; re-derives the closure and requires it to equal the extraction's; loads
  the bundled facade; and runs `tsc` over the facade under the tree's own
  `tsconfig.json` and the commit's Worker ambient types. `tsc` is needed because
  esbuild bundles `export { renamed } from "./x"` without a word when `x` has no
  such export. Only after this passes does it replace the previous output. The
  failures are `VENDORED_TREE_UNBUNDLABLE`, `VENDORED_CLOSURE_MISMATCH`,
  `VENDORED_TREE_UNLOADABLE`, `VENDORED_TREE_TYPECHECK_FAILED` and
  `AMBIENT_TYPES_MISSING`.
- **Provenance.** `entry.ts` says which commit its files are copies of. A facade
  that names any other commit is refused (`AUTHORED_PROVENANCE_MISMATCH`),
  whether it is seeded with `--authored-from` or already in place. A facade that
  names no commit passes. Detection is a hex run of 7 to 40 digits after the word
  "commit", or one that mixes digits and letters; when seeding from a vendor
  directory, any hex run that starts that directory's manifest commit also
  counts. The tool cannot check that the header's count of export tokens is
  still true; the author must.
- **`--out-root`** writes `vendor/` and `analytics-v2-test/` under another
  directory, for a scratch dry run. **`--authored-from`** seeds a new vendor
  directory with the reviewed `entry.ts` and `tsconfig.json`. It is refused
  when the target already holds either, so hand-written files are never
  overwritten.
- **`--report`** writes nothing in the repository. It resolves every patch at the
  commit, runs the parser confirmation when all resolve, lists the files of a
  reference manifest whose blobs differ at the commit, lists facade imports that
  no longer resolve, and lists the commits the facade's provenance text names.
  When the patches and the facade's imports resolve it then builds the commit
  into a temporary directory it deletes, with the same closure, bundle, load and
  `tsc` as a real run (`generation`: `passed`, `refused` with the generator's
  code, or `skipped`). The provenance check is off inside that build, so one run
  shows every blocker. `ok` needs all four: the patches, a facade whose imports
  resolve, provenance text that names no other commit, and a passing build. A
  report with no reference directory has no facade to build with and is never
  `ok`. The exit status is 1 unless `ok`.

## Hand-offs

1. **Vitest and the build do not know a second vendored tree.**
   `vitest.analytics-v2.config.mjs` maps `@app-usagemonitor/*` to the `d43c8f92`
   copies only. A tree for another commit would silently run its kernels against
   this checkout's own packages. The check turns that into a failure, with a
   message naming the config. `cloud-run/build.mjs` hard-codes the same root in
   three places: `VENDOR_ROOT`, the vendored-package guard, and the
   analytics-refresh kernels guard, which raises
   `CLOUD_RUN_BUILD_ANALYTICS_REFRESH_KERNELS_MISSING` when refresh has no inputs
   under it. It fails closed, but an adopter should know before the build does.
   The rest of the consumers are listed under [Review round](#review-round). All
   of these were outside this stream's ownership and are unchanged. Whoever
   adopts a commit edits them, and the path-literal test fails if any still names
   a tree that no longer exists.
2. **The lists are still code, and so is the facade's text.** `EXPORT_PATCHES`,
   `PARITY_SPECS`, `PARITY_HELPERS`, `WEB_ROOTS`, `VENDORED_PACKAGES` and the
   authored `entry.ts` describe `d43c8f92`'s shape. `--report` shows what must
   change for a commit (patch statuses, facade imports that do not resolve,
   missing parity sources, the provenance text, whether the tree builds). The
   change itself is a reviewed edit beside `entry.ts`, including its provenance
   text, which the generator now refuses to leave pointing at another commit.
3. **The check requires the `d43c8f92` tree.** It pins the five patches there. A
   change that removes `vendor/analytics-d43c8f92` must edit the check in the same
   commit. Other `vendor/analytics-<8 hex>` directories are checked against
   their own manifests with the same per-tree assertions. Its bundle and `tsc`
   probe tests still assume that a facade exports `prepareSharedAnalyticsDay`,
   `publicInputs` and `reconcileGroups`.
4. **A stale plan line.** `docs/plans/2026-10-01-gcp-fastpath.md` still says the
   patches are line-pinned and that OAI-3 rebases them. It is a dated plan outside
   this stream, so it was not edited. The line is now wrong.
5. **Not exercised on real data.** The already-exported path (unit-tested and
   manifest-tested on synthetic sources only) and `const` patches (synthetic
   only; the real list has none).
