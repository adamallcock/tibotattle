## What landed

### Wrapper (`apps/worker/src/analytics-v2/public-allowance-breakdowns-v13.ts`)

The module has no imports and uses only erasable TypeScript.

- **`wrapPublicAllowanceBreakdownsV13`** accepts only the vendored projection's
  exact v1.1 envelope, with its keys in order. Anything else is refused, so a
  changed projection can never be relabelled. It makes exactly two changes:
  - it relabels `schemaVersion` in place;
  - it appends `modelConfig` as the last member.

  It never recomputes, reorders or filters a value.
- **`reducePublicAllowanceBreakdownsV13`** is the inverse. It accepts only the
  v1.1 envelope plus a trailing structurally valid `modelConfig`.
- **`buildPublicModelMetadata`** builds the block from a manifest and the
  version's presentation entry.
  - **Roster.** The manifest's models whose provider is `openai_codex`, whose
    allowanceTrack is `primary` and that are not manifest-hidden, in manifest
    order, minus the version's `publicHidden` list.
  - **Id and label** are the manifest's, unchanged.
  - **Bounds.** It enforces the tolerant reader's grammars and bounds: at most
    128 entries, unique ids and unique orders. The id grammar is the
    intersection with `catalog-token-guard-v1`.
  - **Refusal.** A manifest it cannot publish is refused whole, never
    published in part. That includes a hide list naming a model that is not a
    primary Codex model of the manifest, naming one twice or naming a pinned
    one, and a pinned model missing from the roster.
- **Presentation** (`PUBLIC_MODEL_PRESENTATION_BY_MANIFEST_VERSION`). Manifest
  version 1 carries no display section, so a frozen table keyed by manifest
  version stands in:
  - `pinned` for version 1 is the d43c8f92 page's card order with each
    model's `model-visuals.js` theme: astra, 6-sol, 6-luna, 5.6-terra, 5.6-sol,
    5.6-luna, at orders 0 to 5.
  - `publicHidden` for version 1 is the 35 ids above.
  - A roster model that is neither pinned nor hidden would get family
    `generic` and order 6 plus its roster index. None exists in version 1.
  - Any other manifest version fails closed with
    `PUBLIC_MODEL_METADATA_MANIFEST_UNSUPPORTED`.
- **Size.** Version 1 gives 6 entries. Their ids and labels equal d43c8f92's
  `PUBLIC_ALLOWANCE_MODEL_CONFIG`. The sha256 of `JSON.stringify(block)` is
  `8c803481…`, pinned in the spec.

### Route (`community-daily-route.ts`)

- At construction, the route builds the block once from
  `compiledBaselineCatalogManifest()`. That is manifest version 1, which
  KM-CORE proves equal to the `da55288b…` digest.
- The route wraps the vendored graph's breakdowns. Construction throws if the
  baseline cannot be published as metadata.
- `analyticsV2PublicModelMetadata()` is exported as the seam for KM-4, which
  binds a later manifest after cutover.
- **The C-IPR interim frozen read is unchanged.** It serves Cloudflare's frozen
  body verbatim, so its breakdowns keep the version the export carried (v1.0
  to v1.2) and are never wrapped as v1.3.

### Unknown and hidden names

- Only public roster models get a metadata entry.
- A tuple whose id the block does not name keeps its place in `days`. The
  wrapper does not remove it, because removing it would change oracle bytes.
  - A reader that knows the id from its own catalog keeps the tuple uncharted.
    GPT-5.5's tuples in the Q-1 golden take this path on the onmain reader.
  - A reader that does not know the id skips it and states the gap.
- At d43c8f92 an id outside the reviewed catalog cannot occur, because the
  vendored preview validation admits only reviewed catalog ids.

### Parity compare and rehearsal

- **New family.** `scripts/analytics-v2-parity-compare.mjs` (report v4) adds
  the expected family `breakdowns-v13-metadata` and a `breakdownsV13` summary.
- **What is accepted.** A served v1.3 block is accepted only when both hold:
  - it is exactly the v1.1 envelope relabelled, with a trailing
    `modelConfig`;
  - that block equals the committed declared block, including each entry's
    key order.
- **The rest is still compared.** The block's v1.1 reduction is then compared
  with the oracle like any other block. Anything else, such as a changed
  label, a missing or extra entry, swapped orders, a `tone` key, a moved
  `modelConfig` or a `catalogManifestVersion`, is an unexpected
  `allowance-breakdowns` difference.
- **The declared block is a JSON file.** It is
  `apps/worker/analytics-v2-test/fixtures/breakdowns-v13-declared-model-metadata.json`.
  - The compare reads it rather than importing the TypeScript module, because
    the rehearsal's origin child and the edge end-to-end suite run the
    compare under Node 22.16, which does not strip types.
  - The analytics-v2 spec and the PostgreSQL route spec hold the file
    byte-equal to the builder's output over `catalog/manifest-0001.json`.
- **Per-date compare.** `per-date-compare.mjs` (report v2) compares the
  reduced block with the oracle's per-date v1.1 expectation. It fails when
  the declared shape or block is wrong.
- **Rehearsal.** `gcp-fastpath-rehearsal.mjs` adds the gate
  `breakdownsV13Declared` whenever the read serves a breakdown.

## Not done, and why

- **The website reader changes.** They belong to the W-WEB branches and are
  recorded in this stream's integration notes. A committed test that the
  onmain reader keeps GPT-5.5 hidden under v1.3 belongs there too; here it is
  the scratch run above plus this branch's specs, which prove the block never
  names a hidden model.
- **Design fields the reader would refuse.**
  - The design proposed `catalogManifestVersion` and `tone`. The reader's
    envelope and entry checks are exact, so either one would make it reject
    the whole block. Neither is emitted.
  - Manifest version 1 is implied by the v1.3 contract at cutover.
  - Adding either field later needs a reader change first, then a new
    contract version.
- **Presentation in the manifest.** Manifest v1 has no display section. The
  frozen per-version table (pins and hide list) is the stand-in. A later
  manifest that binds metadata (KM-4) must add a table entry or carry
  `display.publicRosterPins` and `display.publicHidden` itself; absence fails
  closed.
- **Edge end-to-end (`npm run edge:e2e`)** was not rerun. Its S9 stage
  compares through the same compare and rehearsal code, which both rehearsals
  above exercise.
