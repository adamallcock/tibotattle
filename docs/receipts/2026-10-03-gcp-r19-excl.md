## The decision it implements

Owner decision round 19 (2026-10-03), EXCL-UNLINKED: "The exclusion lifts
it". An excluded, unlinked participant no longer blocks the daily lane. This
is a deliberate deviation from d43c8f92 parity.

Before this change, an eligible participant with typed evidence (v1, v1.1 or
v1.2) and no active storage owner link made the whole public daily lane
unavailable: every queued day was carried, even when the participant held an
active community aggregate exclusion. That mirrored d43c8f92's daily cohort
refusal (`storage-community-daily.ts` `cohort()`), which ignores exclusions.
The K-CORE-A receipt recorded the question as open.

The separate round 19 answer on departed roster members (their past data
stays included) is not touched here: departed-member handling and the saved
owner sets (E-OWNERSET) are unchanged.

## What changed

| Change | Where |
|---|---|
| The refusal is applied per day. For each computed daily candidate D, the run withholds D only when some unlinked typed participant is **not** excluded on D. The predicate is exclusions.ts `analyticsV2ExcludedOn` (D1's weekly predicate per day: state `active`, scope `community_weekly`, `effective_at` before the end of D, `expires_at` NULL or after its start, in microseconds). Only an answer of exactly `true` lifts a day. Revoked rows never reach the predicate: the reader maps active rows only | `apps/worker/cloud-run/analytics-refresh-read.mjs` (`createAnalyticsV2Pipeline` read and compute) |
| The read side maps each unlinked typed participant to its active intervals by participant id, inside the run's snapshot. No id passes beyond that point. An unlinked entry without a string participant id is refused with `ANALYTICS_V2_REFRESH_OWNERS_INVALID` | same |
| The predicate reaches the Job through `owners.ts`, which re-exports it, so there is one copy of the rule. A pipeline without it cannot be built (`ANALYTICS_V2_REFRESH_PIPELINE_UNAVAILABLE`) | `apps/worker/src/analytics-v2/owners.ts` |
| The receipt's read counts gain `unlinkedBlockedDays`: the computed days the unlinked refusal withheld. It is 0 when every such participant is excluded on every computed day. `unlinkedTypedOwners` keeps its meaning: the roster count, whatever the exclusions | `apps/worker/cloud-run/analytics-refresh.mjs` (`READ_SUMMARY_KEYS`, header) |
| The exclusion contract header names the unlinked case and the second declared difference | `apps/worker/src/analytics-v2/exclusions.ts` |
| Kernel registry entry 5 (closure changed; see below) | `apps/worker/src/analytics-v2/kernel-registry.json`, `apps/worker/scripts/analytics-v2-kernel-registry.check.mjs` |

What does not change:

- An unexcluded unlinked typed participant still blocks every queued day.
- A day outside every active interval still blocks.
- A-2's own blocked days are never lifted by this.
- An unlinked participant is computed by no run and reaches no aggregate,
  excluded or not.
- The allowance preview, the owner-scoped rows and the refusals are unchanged.
- The digest-change requeue (N-EXCL) is unchanged. A new, revoked or edited
  exclusion requeues every published day, and blocked days are carried as
  before. A day lifted by a new row therefore publishes on the next run. A day
  blocked again by a revocation is carried and keeps its prior head.

## EXCL-DEPARTED recovery evidence (2026-10-03)

Recovery started from committed `1e17b82d`. This follow-up changes only the
refresh regression and this receipt. Product source, schemas, the existing
branch-local kernel 5 and its pins are unchanged. Independent review found
that the handover's proposed lookup already exists: the saved-member reader
joins `storage_v11_owner_links` by its unique owner digest regardless of link
state, the refresh maps its participant's exclusions, and compute accepts
saved-member exclusion keys outside the current roster. A genuinely missing
link still blocks publication rather than folding without knowing exclusions.

The new `PG17 EXCL-DEPARTED` regression uses the real roster, owner-set,
exclusion, occurrence and queue readers, real compute, and the Job's store.
It seeds synthetic accountless history, saves a contribution, then makes its
revoked lease graph ineligible through a security disconnect and withdraws
the owner link. It explicitly verifies absence from the real roster and
continued participant resolution through the withdrawn link. The real
`community_aggregate_exclusions` table then demonstrates:

- departure without an effective exclusion preserves the original published
  content, revision and saved contribution rows;
- `effective_at` at the day's end excludes nothing on that day, whereas one
  microsecond earlier hides the saved contribution;
- `expires_at` at the day's start excludes nothing, whereas one microsecond
  later hides it;
- each real-table change moves the exclusion digest and requeues published
  history; an unchanged table requeues nothing;
- revocation restores the original content under a new revision, without
  removing saved data or printing participant identity in the receipt.
