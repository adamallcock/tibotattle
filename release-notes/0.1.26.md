# TiboTattle 0.1.26

Version 0.1.25 was tagged but not published. This release carries its changes
forward. It restores direct Codex allowance reads when recent ChatGPT or Codex
desktop builds place their CLI at `Contents/Resources/codex-cli/bin/codex`.
TiboTattle also checks the older bundled location, system and user Applications
folders, an explicit `CODEX_BIN` setting, and then `PATH`. The doctor identifies
the selected source and bundle layout without displaying a private filesystem
path. Local usage analysis remains independent of the CLI; if a direct quota
read cannot run, the previous observation remains stale. Fresh local usage no
longer relabels that old quota as live. After a terminal refresh timeout, the
dashboard gives cleanup a short grace period before reporting that analysis
did not finish.

On macOS, a locked Keychain can report the same authorization error as an item
access denial. When exactly one matching app credential belongs to a locked
Keychain, TiboTattle now presents the unlock-and-retry guidance. Other access
failures retain the permission-denied guidance. The check is silent and does
not read or replace a credential, change its access policy, or modify the
Keychain search list.

Since the published 0.1.24 release, the desktop source also adds a macOS
update-available indicator, repairs tray cleanup during updater shutdown,
persists startup checkpoints before early quits, warms cached dashboard
reports across periods and speed modes, and corrects the Trends header range
on cached plan views. The model catalog includes newly recognized Claude
names. The forecast-only GPT-6.1 Astra identity remains explicitly unpriced
in local Codex usage reports.

The macOS download requires macOS 14 or later. Each platform's installer and
its verification evidence are listed in the release manifest.
