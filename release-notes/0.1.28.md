# TiboTattle 0.1.28

TiboTattle now recognizes GPT-6.1 Sol as a distinct model and includes its
supported Standard, Batch, Flex, and Fast API-equivalent prices for both context
bands. Observed Ultrafast usage stays separate from Fast in usage and model
performance views. Ultrafast prices are available for the supported Astra
combinations; unsupported model and speed combinations remain explicitly
unpriced. The dashboard explains unavailable rates and distinguishes API pricing
from the allowance included in a subscription.

After a detailed refresh, discoverable older Sol 6.1 logs are reprocessed to
correct model identification and supported pricing while preserving token
totals. Records whose model was stored as unknown cannot be re-identified when
the original log is no longer available. Historical model classification can be repaired locally. Resynchronizing
previously accepted records uses the deployed additive correction contract
and remains pending end-to-end qualification.

Plan labels and expected allowance comparisons now use Pro 10× and Pro Max
25×. The configured expectations place Pro Max 25× at 2.5 times Pro 10×,
Pro 5× at half Pro 10×, and Plus at one tenth Pro 10×. These are product
expectations, not measured provider capacity. The existing Pro identity and
history are preserved, and measured community estimates still depend on
available evidence.

When a log explicitly identifies auto-review, usage from October 6, 2026
(UTC) now appears separately from the main Codex allowance. The marked $0.00
is its main-allowance charge; recorded tokens and API-price evidence remain
intact. Earlier usage keeps its original treatment, and mixed periods show
separate rows. Spark keeps its own measured allowance and timeline.

Detailed refresh reparses available logs for this classification while retaining
older evidence whose source has disappeared. Upgrades preserve event identities
across replay and restart, avoiding duplicate usage. Missing historical metadata
remains unknown.

Accountless performance sharing rechecks its protected sharing preference and
current hosted grant after restart or preference changes before preparing or
sending data. A current grant can resume an earlier authorization or
response-version rejection while preserving acknowledged upload progress.
Ordinary polling cannot retry a terminal rejection, and recorded opt-outs remain
effective. Hosted performance publication still requires separate migration,
activation, and qualification.

A temporary overlap between startup sharing checks no longer permanently
pauses usage sharing. The client retries once the protected preference is
available, while keeping saved opt-outs, current authorization and duplicate
upload protection.

The shared dashboard removes obsolete account, profile, and social controls
while retaining Electron desktop controls, including sharing an image. Project
token mix now shows separate input and output bars, making cached input and
reasoning output easier to compare. Model performance retains every period and
speed view, fixing a case where the default seven-day view stayed on Updating.

Large local review exports now support the runtime’s existing source-file limit,
while preserving older export formats, verification, deletion and recovery.

The desktop runtime updates Electron from 43.2.0 in the published 0.1.26 source
to 43.5.0, with affected transitive dependencies refreshed for security
advisories. The macOS support floor remains macOS 14.

Build tooling removes obsolete download dependencies and retires their temporary
advisory exception. Download integrity, secure transport, cancellation and
platform signing checks remain enforced.
