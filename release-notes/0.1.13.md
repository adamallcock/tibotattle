# TiboTattle 0.1.13

This release repairs the community contribution journey end to end, fixes
usage accounting on large histories, and removes the macOS password prompt
new installs used to see when connecting a Mac.

Requires macOS 14 or later on Apple silicon. Updating keeps your local data,
your Keychain items, and anything you have already contributed.

## Contributing works again

Signing in and approving a contribution could previously stall in a state
that looked signed-in but never finished: a permanently grey **Review and
approve** button, a "Reconnecting" label that never resolved, or a relaunch
that asked you to sign in all over again. Several independent causes are
fixed:

- A completed sign-in now survives quitting the app. If you close TiboTattle
  while the browser is still finishing, reopening it picks the sign-in up
  automatically instead of starting over.
- Contributions waiting on a retry or a paused uploader can be reviewed
  normally. Delivery timing no longer blocks the review.
- A review that cannot be prepared now says so, with **Check again** and
  **Copy diagnostics** beside it, instead of leaving the approve button
  disabled with no explanation.
- Preparation and review are bounded: if something cannot finish, you get an
  explicit retry rather than an indefinite wait.
- Approval records your consent locally before anything is registered with
  the service, so an interruption can leave a Mac that still needs
  connecting — never one registered without your consent.
- A first-time setup on a Mac with no prepared contributions no longer
  deadlocks, and a Mac whose usage index was still building no longer fails
  every refresh with an unexplained collector error.

## Connecting a Mac no longer asks for your password

The upload credential for a Mac is now created by the signed app itself, so
a new install never sees the macOS "wants to access key in your keychain"
dialog. Existing Macs keep working unchanged and migrate quietly the next
time their credential rotates. If macOS ever does ask — a locked keychain,
or an older credential — the app now tells you what to choose and how to
recover if you decline.

## Usage and cost accounting

- **Your numbers stay visible while they are recalculated.** This release
  changes how historical usage is priced, which means previously computed
  figures are recomputed on your Mac. Rather than blanking the view, the app
  keeps showing the previous figures clearly labelled as such until the
  rebuild finishes.
- **The rebuild completes on large histories.** It now runs in a separate
  short-lived process, so a long-running app no longer starves it. Histories
  that previously never finished rebuilding now do.
- **A calibration error is corrected.** Usage that crossed a change in your
  weekly quota window could be dropped from the estimate. Those periods are
  now measured correctly.
- Installs with very large Codex histories no longer hit an internal file
  limit that blanked the dashboard.

## Quota

- The five-hour **Codex Spark** allowance is recognised and named properly
  alongside the seven-day allowance, instead of two identically labelled
  cards.
- **Quota notifications now work.** A defect present since notifications
  shipped meant the presence of a Spark allowance suppressed every
  notification; that no longer happens.

## Clearer status messages

Messages about states that resolve on their own — history still indexing,
quota tracking that started recently — now say what they mean, name the
threshold involved, and no longer use the styling reserved for genuine
problems.

## Privacy

Unchanged, and worth restating: usage data stays on your Mac unless you
explicitly approve contributing it. Contribution covers token counts, model
identifiers, timestamps, quota percentages and similar measurements — never
prompts, responses, file names, paths, commands, or account identifiers.
Diagnostics you copy for support are content-free by construction.

## Verifying this release

Every published artifact is listed with its SHA-256 in `release-manifest.json`
on this release, alongside `SHA256SUMS` and the verification guide in
`docs/verify-release.md`. Anything not listed there is not an official build.
