# TiboTattle 0.1.17

**Status:** Candidate source notes for native dogfood. Integrated RC5 source
produced signed, notarized, and installed build `1023.3`; physical testing then
found that its five-minute ordinary refresh deadline stopped a legitimate full
accounting-cache rebuild. Signed, notarized, and installed RC6 build `1023.4`
proved that timeout correction, then exposed an inherited
`recent_7d_indexing` legacy checkpoint suppressing otherwise-authoritative
unified accounting. RC7 build `1023.5` is allocated to remove only that retired
collector gate while preserving the fail-closed unified-generation authority
check. RC7 still requires exact-source validation, protected R7 regeneration,
signing, notarization, state-preserving installation, and installed native
verification. No stable `v0.1.17` tag, GitHub release, published appcast, or RC7
artifact is claimed yet.

The native Mac app is easier to recover, clearer while it starts, and ready for
the newer Codex history, plan, and quota formats already appearing in current
installations.

Requires macOS 14 or later on Apple silicon. The intended update path preserves
local data, stable Keychain identity, and anything already contributed.

## A steadier native app

The dashboard now explains what it is doing while the local service starts and
while a large history is being analysed. It opens as soon as the primary view is
ready instead of waiting for every secondary load, and startup failures name the
phase that failed so the suggested recovery step is relevant. If primary
readiness arrives after the initial wait, the native app now keeps observing the
same fenced document generation, refreshes once, and replaces the timeout page
after the late primary result succeeds rather than requiring a manual reload.

A collapsed sidebar can always be reopened from the toolbar, the View menu, or
the keyboard. The native window also stops offering unused tab controls, its
context menus behave consistently, and the Share toolbar button opens the Share
card it promises.

The new Forest Ink dark appearance can follow the system or be selected
directly. Left-clicking the menu-bar item now opens a compact native status
popover with the current Five-hour and seven-day allowance lanes, 7/30-day
usage and cost history, and a weekly pace outlook when matching evidence is
available. Right-click and Control-click retain the native actions menu. The
popover keeps the latest measured allowance visible during a refresh and can
retain compatible, previously validated usage history with a clear retained-data
label. When both Five-hour and seven-day lanes make the instrument taller than
the space below the status item, it opens at the top and scrolls vertically so
neither the first lane nor the lower history and actions are clipped. It hides
history or pace when the supporting evidence is unavailable; it never presents
retained history as fresh or fills a gap with zero or a guessed forecast. An
offline update check is also distinguished from broken update infrastructure.

## Codex history keeps moving

Current Codex versions can keep more than one immutable rollout for one logical
thread, including after a paginated history revert. Older TiboTattle builds
treated that valid shape as a duplicate identity and could leave the local index
stuck retrying it.

0.1.17 understands the thread and rollout lineage separately. It carries the
correct cumulative baseline into the next generation, suppresses replayed
history, and still fails closed when source identity or lineage is genuinely
malformed. Copied or repeated valid session metadata no longer makes an
otherwise valid rollout unreadable.

An inline fork whose parent history is unavailable is now withheld when replay
suppression cannot be proved. The guard also covers the legacy collector, so
inherited parent activity cannot be charged again as new fork usage. This is an
explicit coverage limit, not evidence of zero usage.

New Codex thread-source labels remain privacy-safe and conservative: unreviewed
labels stay unavailable rather than being guessed into the wrong category. The
command-line doctor also reports which Codex binary TiboTattle selected and the
version that binary returned.

## Plan and allowance names match current Codex

The app now recognizes the current Codex plan contract and renders audited human
names instead of exposing internal identifiers. The ordinary 300-minute pool is
called **Five-hour allowance**, Spark remains a separate allowance, and other
observed pools remain distinct without being promoted into the headline or
silently merged into normal Codex usage.

Sparse or windowless quota updates are accepted when they are valid. A malformed
window is withheld with a diagnostic, so missing evidence cannot turn into a
confident zero or corrupt the allowance history; valid usage, tool, and other
quota facts from the same rollout remain available.

## Local history follows the selected plan era

Current and historical plan evidence now stays attached to its compatible era.
The selected estimate, history, comparison range, forecast, and share card all
use the same selected population instead of borrowing a more complete-looking
result from a different plan. Useful retained history survives when account
identity is missing, while conflicting or unsupported attribution remains
explicitly unavailable.

This is conditional local attribution, not proof of an account-exact billing
identity, workspace identity, cross-device equivalence, provider-authoritative
quota formula, or bill. The local SQLite schema remains version 11; the change
reanalyses derived accounting evidence without wiping the retained ledger or raw
history.

## Large-history and retained-data honesty

Fallback archive accounting now has a memory policy designed for the resident
menu-bar process instead of inheriting the much larger allowance used by a
short-lived rebuild. Cache-reuse reporting also distinguishes warm reuse,
configuration changes, and post-compaction work.

When a fast refresh keeps previously verified figures on screen, the dashboard
now says that those figures are retained while history advances. It no longer
claims that visible totals are still loading or hidden.

Large macOS history indexing now runs off the companion's loopback event loop,
so health, progress, and Cancel remain responsive while SQLite is working. A
fresh missing index uses the bounded parallel cold-rebuild path instead of the
single-lane incremental path, and strict content-free counts show how many
rollout files have been selected and processed. The browser and native toolbar
remain attached through the fresh-build bound instead of reporting a still
running first pass as finished. The measured cold path now has a four-hour
fresh-build bound; ordinary existing-index refreshes retain their five-minute
bound. A source rejected late in a fresh rebuild is cleaned only after the
required indexes exist, so the safety window is not consumed by repeated
full-table scans. Cancellation or timeout preserves the last
published generation and does not trigger another expensive full reload.

Refresh copy no longer turns a successfully loaded but empty or withheld
overview into “Headline ready.” It says only that the local summary was updated
while full history is still being checked; unavailable figures remain
unavailable.

Verified partial history is presented as a coverage limit rather than an app
failure. The compact toolbar badge stays compact, while the in-page history
panel carries the fuller explanation and progress treatment. Hard refresh and
integrity failures remain visually distinct.

The internal partial-tool-history warning no longer appears as a dashboard
warning. Its coverage state is preserved, and missing tool totals are still
withheld rather than shown as zero.

The last authoritative dashboard snapshot now survives an app relaunch. The
native dashboard can therefore show the most recently verified figures, clearly
labelled as retained, while a fresh analysis catches up. If neither the current
index nor a compatible snapshot can support a figure, it stays unavailable
rather than becoming a confident zero.

## Clearer costs and cache-drop details

The headline is now a speed-priced API equivalent: event-time Standard API
prices with the published Priority/Fast price ratio where available. Missing
published ratios and uncertain speed modes keep their disclosed assumptions or
unknown status. API pricing remains a measuring stick, not your bill or a claim
about the subscription's quota formula.

Accounting shows one headline amount instead of competing Standard and
speed-priced amounts. Switch and cache-continuity overhead can show the covered,
priced estimate even when some sessions lack exact event order, with the partial
coverage explained below the figure. Missing coverage is not filled with zero
or promoted into a whole-period total.

Full-history headlines and usage timelines now retain the same input-context
pricing evidence and existing missing-context compatibility rule as the
accounting cache. This fixes a disagreement where older large-input events
could receive different API-equivalent prices in those views without any
difference in their token totals.

The recent cache-continuity table uses **Configuration**, removes the
**Estimated lost reuse** column for space, and shortens **Standard API
equivalent** headings to **API equivalent**. Header help still identifies the
Standard-rate basis; the underlying calculations are unchanged. Cache-reuse
tooltips also remain readable in dark appearance.

Both recent cache-drop tables can show a thread-name link back to Codex. A
recorded worker relationship has separate parent and worker links; a missing
name uses a shortened identifier, and ambiguous attribution stays unlinked.
Timestamps remain available in hover and accessible descriptions. This lookup
is local and transient: names and links are not stored in accounting snapshots,
exports, diagnostics, or contribution payloads, and missing optional names do
not block the accounting view.

## Existing local data moves forward safely

0.1.17 introduces local unified-index schema 11. The shipped 0.1.16 app created
schema 8; newer development and dogfood code may have created schema 9 or
schema 10. This candidate checks each supported predecessor read-only first.
Schema 8 and 9 predate the current source-identity contract, so the normal app
path rebuilds a validated schema-11 stage from readable raw history. Schema 10
already has the current physical identity contract and is cloned and migrated
additively. The separate parser v10-to-v11 upgrade still reprocesses readable
sources; only an unchanged source with current parser and source provenance can
be reused without rescanning. Neither path replaces the live index until its
candidate passes validation. Schema 11 adds the two usage lookup indexes
required for bounded source quarantine and orphan quota cleanup. Parser v11
separately retains valid source facts when one quota window is malformed and
accepts Codex's segment-start paginated lineage reset without inheriting
snapshots from the replaced branch.

The newer-schema safety boundary begins with this compatibility-aware code. A
0.1.17 build that encounters a schema newer than 11 refuses it before writing
and presents local figures as unavailable instead of relabelling, downgrading,
or wiping the data. The shipped 0.1.16 binary does **not** have that guarantee:
it opens the database writable and may touch SQLite journal mode before its
generic schema rejection. After schema-8, schema-9, or schema-10 state has
advanced to schema 11, do not reopen it with 0.1.16. Preserve the rollback copy
and use a
newer compatible build or the explicit recovery procedure instead.

Normal forward migration remains the first path. If an index cannot be migrated
normally, the recovery command now uses a separate prepare/apply workflow: it
builds and validates a copy before an explicit replacement step. The original
index and raw local Codex history remain in place while recovery is prepared.

## Safer Preview and native release boundaries

Preview is now a genuinely separate local app: **TiboTattle Preview.app** uses
its own bundle identifier, `usagemonitor-preview://open` route, Application
Support directory, preferences, Keychain namespace, and `/preview/appcast.xml`
feed. Installing or updating Preview cannot target the stable app or its state,
and Preview never opts into automatic updates.

Internal dogfood is deliberately different: it keeps the stable bundle and
local-state identity so it can test an in-place upgrade, while using its own
update channel. Earlier 0.1.17 internal candidates used builds **1023**,
**1023.1**, **1023.2**, **1023.3**, and **1023.4**. RC7 is allocated build
**1023.5**, while **1024** remains reserved for the stable final, keeping stable
ordered after the candidate. Signed tooling also requires a clean checkout and
exactly one matching annotated source tag at `HEAD`: `v0.1.17` for stable, or
the strict
`tibotattle-internal-dogfood-0.1.17-rcN-source-YYYYMMDD` form for a dated
candidate.

RC5 build `1023.3` is signed, notarized, and installed evidence only for its
frozen source. It preserved schema-11 data and launched without an automatic
Keychain prompt, but its full accounting-cache rebuild exceeded the ordinary
five-minute refresh deadline. RC6 build `1023.4` then passed source, R7, signing,
notarization, state-preserving replacement, and installed launch gates; its real
refresh ran beyond five minutes and reached terminal success. That run exposed
an older `recent_7d_indexing` checkpoint still withholding advanced accounting
even though the unified generation itself was authoritative. RC7 removes only
that retired checkpoint dependency. It does not relax
`unifiedGenerationAuthoritative`, source completeness, generation matching, or
atomic cache publication, and must repeat every exact-source and installed gate.
No 0.1.17 artifact has been published or made available through an updater.
Browser rendering and compiled native tests do not prove physical popover
interaction or thread-link handoff to Codex.

## Prompt-free credential upgrades

Automatic launch, refresh, contribution, and credential-migration paths now
forbid Keychain interaction prompts. A compatible legacy credential is retried
non-interactively up to three times. If macOS still refuses access, the app keeps
local analysis available and offers an explained, deliberate recovery action in
Settings; only that user-initiated fallback may request approval. It does not
grant a blanket ACL, store a secret outside Keychain, or silently reset identity.
An unexpected automatic Keychain prompt remains a release blocker.

## Disconnect this Mac without deleting history

The Community panel replaces self-service hosted-delete controls with confirmed
**Disconnect this Mac**. Disconnect pauses this Mac's contribution delivery,
revokes its device authority, and clears its local device credential and binding.
Previously contributed hosted history, other devices, and local analysis remain
intact. The pause survives a restart and cannot be silently undone by an
automatic retry; reconnecting requires explicit review and approval. Signing out
is a separate action, not a substitute for disconnecting.

Local data erasure, hosted export, and private owner-operated hosted erasure
remain separate operations. Owner erasure retains upload fences, aggregate
withdrawal, independently verified tombstones, identity cooldown, and
deletion-safe restore safeguards. Removing the self-service control does not
change retention periods or erase previously accepted data.

The desktop update and hosted service deployment are separate. The merged
Worker source makes `DELETE /api/v1/me` return `404 NOT_FOUND` without participant
mutation, but that endpoint retirement has **not been deployed by this release
work**. Installing the candidate changes its desktop controls, not the live
Worker endpoint or controls in older installed apps.

Before a separate hosted cutover, the owner must verify independent owner
access, account for unfinished deletions, resolve private privacy-request
intake and identity verification, and verify retention/backup disclosures.
Those requirements remain open; this candidate establishes no new contact
channel, response deadline, or conclusion about applicable privacy rights.

## Public community view

The public community page can show the merged measured allowance across plans,
and its compact platform selector states which downloads are actually
available. The graph stays aligned with its explanation when the page changes
shape.

The hosted admin source also adds a **By model** view for Sol, Terra, Luna, and
GPT-5.5 with the existing Pro-20x normalization and identification gates. It is
not activated by this desktop release: Worker migration 0041, deployment,
warming, and real cohort data remain separate operational gates.

PR #94 also includes a closed telemetry v1.1 account/plan transport and
lifecycle, but it remains staged source. Worker migrations 0042-0044, hosted
activation, and a new explicit consent are separate operations. Installing the
desktop app neither deploys that protocol nor changes an existing contribution
consent.

The fixed-real-corpus, before/after attribution comparison required by the PR
#94 plan remains **OPEN / NOT RUN** and has not been represented as passed by
R7. Existing tools provide partial content-free aggregates but no reviewed,
schema-validated cross-revision comparator with the required reconciliation and
resource receipt. An explicitly open-gate internal dogfood may be used for
testing, but this empirical gate must be closed or deliberately resolved before
stable or public qualification.

## Known limitations

This candidate remains the native macOS app. It does not include the new
Electron application, and Windows and Linux desktop support are not claimed by
0.1.17.
Unfinished Claude Code usage-monitoring integration work is also excluded.
Claude-related carryover is limited to dormant local/export compatibility
scaffolding inherited from `main` and removal of the inactive quota route;
0.1.17 does not collect, display, or claim Claude Code usage.

Hours when your weekly allowance is exhausted and you keep working on purchased
credits remain excluded from the cost view; surfacing that spend properly is
still planned.
