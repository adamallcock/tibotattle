# TiboTattle 0.1.18

TiboTattle 0.1.18 adds GPT-6 Astra accounting, fixes paginated Codex history
handling, and introduces a separate Intel Mac installer alongside Apple silicon.
Both require macOS 14 or later. The stable build is `1026`; the final release
manifest identifies each architecture's exact installer and verification evidence.

**Provenance:** [GitHub release](https://github.com/adamallcock/tibotattle/releases/tag/v0.1.18) ·
[annotated source tag](https://github.com/adamallcock/tibotattle/tree/v0.1.18) ·
[changes since v0.1.17](https://github.com/adamallcock/tibotattle/compare/v0.1.17...v0.1.18).

## Codex and GPT-6 Astra compatibility

The app recognizes GPT-6 Astra and other reviewed OpenAI models throughout
local accounting and the admin model dashboard. Astra pricing covers Standard,
Batch, Flex and Fast, including cache writes and the request-specific long-context
boundary. Missing token components remain unavailable instead of becoming zero.

Changing Astra's reasoning effort is no longer automatically classified as a
cache reset: cache analysis uses model-specific effort semantics and measured
cache behavior rather than assuming continuity or loss. Current Codex
compaction headers, including their new ordinal field,
are recognized so compaction remains part of cache-drop attribution. Read-only,
bounded Zstd support restores coverage for compressed Codex histories on runtimes
with native Zstd support.

Resumable metadata exports now accept paginated histories that start at ordinal
zero with no physical history base. Logical forks remain independent, repeated
physical generations retain distinct occurrence identities, and copied legacy
tool calls are suppressed consistently. Frozen exports keep their original
parent selection across resume. Older incompatible export workspaces are
refused before mutation; exact physical-base continuations remain unsupported
in the checkpoint export lane rather than being approximated as resets.

Paginated accounting also keeps inherited settings at the correct history
boundary. A reset without model or speed evidence stays unknown; it cannot
borrow the parent's later settings during reanalysis and change historical
pricing attribution. Explicit physical-base continuations retain their pinned
settings, including unknowns, consistently across rebuild and resume.
Descendants use the selected history rather than retired exports, preserving
real usage after a reset without borrowing discarded settings or snapshots.

The admin model view includes all 39 reviewed OpenAI identities, supports
filtering, preserves older history and keeps Spark's allowance separate.
Response-level usage records continue to reconcile through the existing legacy
stream; response-only histories and applied reasoning updates remain unqualified.
API-equivalent pricing remains a comparison measure, not a provider bill or a
claim about subscription allowance formulas. Installing the desktop release
does not apply hosted migrations or activate the hosted admin view.

## Separate macOS installers

This is the first release with separate Apple silicon (`arm64`) and Intel
(`x64`) installers for macOS 14 or later, built from one release source. It addresses
[issue #93](https://github.com/adamallcock/tibotattle/issues/93) without changing
the already published 0.1.17 assets or tag.

The Intel build uses the native launcher, bundled Intel Node runtime and native
Keychain broker. Its updater uses a separate feed; existing Apple silicon
update URLs stay unchanged. The website has separate macOS tabs and exposes
Intel downloads only when their own validated release evidence is supplied.

Stable build `1026` follows private RC3 `1025.2`; earlier RC1 `1025` and RC2
`1025.1` artifacts remain unchanged. Private candidates are not relabeled as
stable, and their checks do not substitute for final stable-artifact evidence.

The release corrects the first-upgrade refresh deadline: reviewed published parser
v10/v11/v12/v13-to-v14 rescans receive the bounded four-hour cold-refresh window,
so a large reanalysis is not interrupted by the ordinary five-minute limit.
Warm refresh deadlines and compatibility safeguards remain unchanged.

## Qualification boundary

For this release only, the owner accepted the missing disposable-profile
manual Login Item/lifecycle matrix and physical Intel qualification, and
authorized both Mac installers to proceed to publication. The owner reports
other testers are running the app successfully; this is user-reported feedback,
not a retained architecture-, source- or artifact-bound qualification receipt.
Cross-compilation and Rosetta do not prove physical Intel behavior. The exact
scope and retained safeguards are recorded in the
[0.1.18 manual-qualification waiver](https://github.com/adamallcock/tibotattle/blob/v0.1.18/docs/decisions/2026-09-05-release-0-1-18-manual-qualification-waiver.md).

The waiver does not waive data-loss or integrity failures, final signing and
notarization, updater verification, or unexpected Keychain security prompts.
Do not bypass macOS protections or reopen upgraded state with an older app.
No Windows, Linux, Electron or new Homebrew Intel support is claimed. Hosted
migrations, device pairing and contribution activation remain separate from
the desktop release and retain their consent requirements.

Follow the [Intel implementation plan](../docs/plans/2026-09-03-macos-intel-release.md)
and [macOS release runbook](../docs/runbooks/macos-stable-release-runbook.md).
